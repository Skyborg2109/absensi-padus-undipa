# AGENTS.md — absensi-padus-undipa

## Commands
- `npm run dev` — Vite development server.
- `npm run build` — production build; this is the only configured verification command.
- `npm run preview` — serve the production build locally.
- No test, lint, typecheck, formatter, CI, or task-runner scripts exist. Do not invent them; use `npm run build` after code changes.
- Never hand-edit `dist/`; it is generated by Vite.

## Project shape
- Single Vite app, not a workspace: `package.json` scripts are the only task entrypoints.
- Stack: Vite 8, React 19, React Router 7, Tailwind CSS 4 through `@tailwindcss/vite`, `html5-qrcode`, `qrcode`, and `@supabase/supabase-js`.
- Runtime flow: `src/main.jsx` → `src/App.jsx` → role-guarded routes in `src/pages/`.
- `src/App.jsx` wraps the app in `PenyediaAuth` then `PenyediaToko`; admin routes are `/admin/:tab`, member routes are `/anggota/:tab`.
- Admin tabs are declared in the `TAB` array in `src/pages/Admin.jsx`; member tabs are declared in `src/pages/Anggota.jsx`. URL tabs use `useParams` and unknown tabs fall back to `dasbor`.
- Shared visual/code components are in `src/components/ui.jsx`; custom classes are in `src/index.css`. Reuse `.btn`, `.buku`, `.baris`, `.pita`, `.lencana`, `.tab-buku`, `.lembar-qr`, `.tabel`, and `.toast` rather than adding a second design system.
- UI copy and identifiers are predominantly Indonesian; keep new UI text and domain names consistent with the existing style.

## State and authentication seams
- `src/lib/toko.jsx` is the shared store for `daftarAnggota`, `jadwal`, `sesi`, `absensi`, `pengajuan`, and `notifikasi`. When Supabase env vars are present it hydrates, subscribes to Realtime changes, and writes these tables remotely; a 30-second polling fallback covers missed events. Otherwise it falls back to `localStorage` key `padus-toko-v2`. It is mounted once in `App.jsx`; use `pakaiToko()` rather than creating local copies of shared data.
- `src/lib/supabase.js` reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`; `.env.example` contains the placeholders. Never commit a service-role key or real secrets.
- `supabase/migrations/0001_supabase.sql` creates the tables, RLS policies, helper functions, and initial profiles; `0002_schedule_fields.sql` adds normalized schedule times; `0003_realtime.sql` publishes the shared tables to `supabase_realtime`; `0004_optional_nim.sql` allows name-only or NIM-only member profiles; `0008_sync_auth_display_name.sql` mirrors `profiles.nama` into `auth.users.raw_user_meta_data` so the Auth dashboard Display name column is filled; `0009_backfill_session_times.sql` fills missing `sesi.mulai_menit`/`batas_menit`/`batas_tepat` (a null `batas_menit` made every scan count as late); `0010_fix_mislabeled_late_scans.sql` re-labels late scans that were actually within the on-time window. Apply migrations with the Supabase CLI or SQL Editor before using remote mode. Admin Auth users must be linked to a `profiles.user_id` before they can pass `is_admin()`.
- `supabase/functions/create-member/index.ts` is the only place allowed to create member Auth users. It verifies the caller is an active admin, uses the server-only `SUPABASE_SERVICE_ROLE_KEY`, creates `<NIM>@undipa.ac.id`, and links the new user to `profiles.user_id`; deploy it with `supabase functions deploy create-member`.
- `supabase/functions/login-member/index.ts` accepts NIM or exact full name plus password, resolves the active member profile server-side, and returns a Supabase session; `supabase/config.toml` sets `verify_jwt = false` because this function is the anonymous login entrypoint. Deploy it with `supabase functions deploy login-member`.
- `supabase/functions/set-member-password/index.ts` is the only place allowed to overwrite a member's password. It re-checks the active admin, requires an active member profile, then calls `auth.admin.updateUserById`; `ubahAnggota(id, { ..., sandiBaru })` in `toko.jsx` invokes it only when a new password is supplied. Deploy it with `supabase functions deploy set-member-password`.
- `src/lib/auth.jsx` is the authentication seam. With Supabase env vars, member login accepts NIM or exact full name through the `login-member` Edge Function and uses `profiles.role`; internally the function authenticates the derived `<NIM>@undipa.ac.id` email. Admin uses `VITE_SUPABASE_ADMIN_EMAIL`. Without env vars it keeps the local demo credentials and session behavior.
- Admin member CRUD is implemented in `toko.jsx` (`tambahAnggota`, `ubahAnggota`, `hapusAnggota`, `aktifkanAnggota`) and rendered by the `Anggota` function in `src/pages/Admin.jsx`. In Supabase mode, adding a member calls the Edge Function and requires an initial password; deletion is a soft deactivation (`aktif=false`) and the admin panel can reactivate it without deleting history.
- The intended backend is Supabase Auth/Postgres/RLS, but no Supabase project credentials are present in this repository. Do not assume a project has been provisioned.
- `aturUlang()` is local-demo-only; in Supabase mode it refuses to delete remote production data.

## Attendance implementation
- `src/pages/Admin.jsx` Sesi renders a real scannable QR with `QrSesi` from `qrcode`; `src/pages/Anggota.jsx` scans it with the dynamically imported `html5-qrcode`.
- `src/pages/Anggota.jsx` Pindai dynamically imports `html5-qrcode` for camera scanning, then uses browser `navigator.geolocation` and haversine distance to the hard-coded aula coordinates (-5.1405, 119.4832).
- Attendance is check-in only: QR, GPS, and time are all required. GPS unavailable, out of radius, invalid/paused/closed token, or a duplicate member/session scan must fail clearly; never silently widen the radius.
- The attendance radius is a hard default of 100 m. The 500 m campus area is only a location display heuristic, not an attendance allowance.
- Camera/geolocation flows require browser permission and HTTPS or localhost. Attendance auto-validates after QR success; the “Mode uji” slider is only an explicit test fallback.
- `bukaSesi()` creates the session token and `batasMenit = current time + toleransi`; session statuses are `terbuka`, `jeda`, and `ditutup`.

## Business rules from `prd.md`
- Late latihan: Rp5.000 per event; absent latihan: Rp10.000; absent gladi: Rp25.000; late pengukuhan: Rp25.000.
- Base fee is Rp250.000. Three absences makes a member ineligible; absence at pengukuhan means zero fee, not merely a deduction.
- Do not double-count events. Closing a session identifies unscanned members as candidates pending admin verification; it is not a final penalty automatically.
- RULE-09 bonus amount is explicitly undecided; leave it as “menunggu keputusan” rather than inventing a value.
